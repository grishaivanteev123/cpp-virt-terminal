2. Поддерживаемые команды.
Программа поддерживает следующий набор CRUD-операций и команд:
help - Выводит список всех доступных команд.
ls - Показывает содержимое текущей директории(не показывая при этом скрытые директории или файлы).
cd <name> - Переход в другую директорию имени <name>. Также поддерживается возврат в предыдущую директорию через ".."
cat <name> - Вывод содержимого файла имени <name>
touch <name> [-m] - Создание нового файла имени <name>.По умолчанию создается однострочный файл(SingleLineFile), через флаг -m создает многострочный файл(MultiLineFile).
mkdir <name> - Создание новой директории(директорию с пустым именем создать нельзя)
rm <name> - "Удаляет" сущность имени <name> (на самом деле делает скрытой, и оставляет в памяти).
restore <name> - Восстанавливает ранее "удаленную" сущность.
mv <old> <new> - Переименовывает сущность <old> в имя <new>
edit <name> - Редактирует файл имени <name>. Поведение (однострочное или многострочное) определяется типом файла полиморфно.
exit - Завершение работы терминала.


3. Авторитарные решения.
1) Где определяется свойство скрытости?
Внутри базового класса Entry. Свойство hidden является общим атрибутом для любой сущности. Вынос этого поля в Entry позволяет: использовать единый механизм hide() и restore() для всех наследников, реализовать рекурсивное скрытие в классе Directory: когда мы скрываем папку, она просто вызывает hide() у всех своих детей через указатель на базовый класс, не заботясь о том, файл это или директория.
2) Где происходит фильтрация скрытых файлов при ls?
На стороне класса Directory (в методе listAll).
Terminal не должен знать о внутреннем состоянии объектов (скрыты они или нет). Именно Directory решает, какие из её детей могут быть отображены в данный момент. Это упрощает код Terminal, избавляя его от лишних проверок if (!child->isHidden()).
3. Где реализован поиск сущности по имени?
Совместная логика Directory и Terminal. Я разделил обязанности:
Directory::findEntry берет на себя "техническую" часть: перебор вектора и сравнение строк. Она возвращает просто Entry* (или nullptr).
Terminal берет на себя "логическую" часть: он интерпретирует результат. Например, при команде cd терминал проверяет с помощью dynamic_cast, является ли найденная сущность именно директорией. Это позволяет методу поиска оставаться универсальным для всех команд (cat, rm, edit).
4. Как организован текущий путь (cwd)?
Через хранение вектора указателей на директории (std::vector<Directory*> path).
Нам не нужно каждый раз искать родителя или пересчитывать путь от корня. Последний элемент вектора (path.back()) всегда является текущим каталогом.
Вектор по сути хранит всю цепочку от корня до текущей точки, что позволяет мгновенно реализовать команду cd .. (просто pop_back())
5. Как устроен переход между директориями?
Через явное добавление и удаление директорий в path.
Когда пользователь вводит cd folder, мы находим указатель на объект folder и делаем push_back.
Когда пользователь вводит cd .., мы делаем pop_back.
Это исключает ошибки, связанные с потерей ссылок на родительские элементы в дереве, и гарантирует, что мы всегда знаем точную иерархию, в которой находится пользователь в данный момент.
