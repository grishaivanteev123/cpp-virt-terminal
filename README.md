1. Сборка и запуск программы.
   g++ Terminal.cpp Directory.cpp Entry.cpp Directory.cpp SingleLineFile.cpp MultiLineFile.cpp -o Terminal.exe

2. Поддерживаемые команды.
   Программа поддерживает следующий набор CRUD-операций и команд:
   help - Выводит список всех доступных команд.
   ls - Показывает содержимое текущей директории (скрытые файлы и директории не отображаются).
   pwd - Показывает текущий путь без префикса.
   cd <name> - Переход в другую директорию с именем <name>. Также поддерживается возврат назад через "..".
   cat <name> - Вывод содержимого файла с именем <name>.
   touch <name> [-m] - Создание нового файла с именем <name>. По умолчанию создаётся однострочный файл (SingleLineFile), через флаг -m создаётся многострочный файл (MultiLineFile).
   mkdir <name> - Создание новой директории (директорию с пустым именем создать нельзя).
   rm <name> - "Удаляет" сущность с именем <name> (делает её скрытой, но объект остаётся в памяти).
   restore <name> - Восстанавливает ранее "удалённую" сущность.
   mv <old> <new> - Переименовывает сущность <old> в имя <new>.
   edit <name> - Редактирует файл с именем <name>. Поведение (однострочное или многострочное) определяется типом файла полиморфно.
   exit - Завершение работы терминала.

3. Архитектура проекта.

1) Где определяется свойство скрытости?
   В базовом классе Entry. Поле hidden является общим атрибутом для любой сущности. Это позволяет использовать единый механизм hide() и restore() для всех наследников и реализовать рекурсивное скрытие в классе Directory: при скрытии папки она вызывает hide() у всех своих детей через указатель на базовый класс, не заботясь о том, файл это или директория.

2) Где происходит фильтрация скрытых файлов при ls?
   В классе Directory (метод listAll()). Terminal не должен знать о внутреннем состоянии объектов (скрыты они или нет). Directory решает, какие из её детей отображать. Это упрощает код Terminal и избавляет его от лишних проверок.

3) Где реализован поиск сущности по имени?
   Совместная логика Directory и Terminal. Я разделил обязанности:
   - Directory::findEntry выполняет техническую часть: перебор контейнера и сравнение строк. Она возвращает Entry* или nullptr.
   - Terminal интерпретирует результат: например, при команде cd проверяет через dynamic_cast, является ли найденная сущность директорией. Это делает поиск универсальным для всех команд (cat, rm, edit и т.д.).

4) Как организован текущий путь (cwd)?
   Через хранение вектора указателей на директории (std::vector<Directory*> path). Последний элемент path.back() всегда является текущим каталогом.
   Это позволяет мгновенно реализовать команду cd .. (pop_back()) без поиска родительской директории в дереве.

5) Как устроен переход между директориями?
   Через явное добавление и удаление директорий в path.
   При команде cd folder мы находим указатель на объект folder и делаем push_back.
   При команде cd .. выполняем pop_back.
   Это исключает ошибки, связанные с потерей ссылок на родителя, и гарантирует сохранение иерархии директорий текущей сессии.

6) Владелец объектов и память.
   В проекте используется std::unique_ptr в классе Directory для хранения дочерних элементов. Это снимает необходимость ручного удаления объектов и делает управление памятью безопаснее.
